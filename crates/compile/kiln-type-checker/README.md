# Source checker

`kiln-type-checker` owns source binding, inference, narrowing, type relations and TypeScript diagnostics. Its algorithms are ported from Bun's `src/sema`, first at `bbdc5a519e0a06d1b3133b564f91096b9ba10a31` and now synchronized with `43a42a836b` (#44665 and #44685, which fix differences from `tsc` 7.0.2), including the Microsoft TypeScript checker/binder ports. The engine under `src/engine` stays a near-verbatim port, so upstream changes merge three ways after normalizing Bun's `crate::` paths to `crate::engine::`; Bun's own parser, command line and driver are not ported. `NOTICE` records provenance; `LICENSE-APACHE-2.0` covers the Microsoft portions and declaration libraries.

The public input is an immutable `SourceSnapshot` of owned Kiln modules, auxiliary package metadata, roots and checker options. Oxc captures original type syntax and original executable syntax from its authored parser result before transformations. Transformed modules retain an immutable, acyclic authored-module sidecar; execution continues to use generated JavaScript coordinates. Checker input and diagnostics use authored coordinates, and compiler contract attachment crosses through the frontend source map. The private adapter builds the checker representation; it does not parse source again. No donor AST, arena lifetime, symbol ID or type ID crosses the crate API.

The checker returns owned type descriptions, coarse contract classes, diagnostics and a completeness flag. An adapter gap or exhausted stack budget makes a result incomplete. Incomplete results cannot supply bytecode specialization hints. Source contracts, including TypeScript `any` and unchecked assertions, are never Value Graph proofs.

The database receives source checking through a function pointer at the composition root, preserving ADR 0001 and the layer boundaries of ADR 0066. Its memo reads the active source set, shared parsed modules, and explicit JSON/JSONC metadata revisions. The daemon lazily checks immutable graph snapshots through a bounded singleflight cache keyed by entry and complete source identity, outside the state mutex. Compiler callers request function contracts only, avoiding expression-type formatting; diagnostics are unchanged. Bytecode metadata carries the checker identity and its own format version. Numeric aliases therefore reach the existing guarded specialization candidates without creating another executable lowering path (ADR 0061).

The engine interns types and uses dense query tables, task-local buffers, publication barriers and per-session mimalloc arenas. The snapshot host runs the donor's parallel load, bind and resolution phases and its planned checking steps (tasks, then validate, link and publish barriers, with invalid tasks checked again) on one process-wide pool of worker threads (the available CPUs, bounded by positive `KILN_JOBS` or `RAYON_NUM_THREADS`). Checker heaps do not advise transparent huge pages: each worker's heap starts on fresh memory, and zeroing 2 MiB pages on first touch made a 16-thread load slower than a serial one. A caller with an insufficient stack runs on a scoped worker with an explicit stack allowance. Standard ECMAScript, DOM and worker declaration libraries are pinned TypeScript 7.0.2 inputs; they are not ambient filesystem dependencies. `Libraries` holds them as source and parses each with the frontend the composition root supplies the first time a check loads it, so a check pays only for the libraries its `lib` setting references. The daemon parses them with `kiln_frontend_oxc::parse_authored`, which builds only the authored module the checker reads, and `Libraries::prepare` parses a `lib` closure ahead of a check.

The Rust toolchain is pinned through mise to `nightly-2026-09-15` for `allocator_api`. Run `mbx` commands under that toolchain. Run the repository gate once after a completed change, retaining its full evidence.

Package managers' symbolic links reach the checker as `SourceSnapshot::links`, which the host follows as a file system would; the CLI records them for the `node_modules` directories of the packages it captures (`kiln_hir::source_types::CHECKER_LINKS_FILE`). JavaScript arrives as text and is parsed only if a program loads it. Declaration files receive no facts, since they compile to nothing, and `FactSelection::None` serves callers that keep no compiled program. Current integration limits: source-set changes conservatively invalidate TypeScript facts. Uploaded tsconfig JSONC and its extends chain supply compiler options; package manifests and declaration targets are explicit snapshot inputs. The CLI captures checker metadata separately from its runtime source walk. The nearest uploaded tsconfig governs daemon checks. Configuration syntax and option errors disable compiler hints. This remains an integration rather than a claim of full TypeScript compatibility. Unsupported owned-syntax adaptation is reported explicitly and disables optimization hints.

Compatibility is measured against `tsc` 7.0.2 with Bun's `test/cli/check/differential-cases.json` through `examples/tsc_differential.rs`, which prints a project's diagnostics as `tsc --pretty false` does. Reference implementations are research inputs, not additional executable checker pipelines. `pingdotgg/ts-rust` (`tsc-rs`), `maschwenk/tsrs`, and `kazhiramatsu/tsc-rs` inform targeted TypeScript-oracle regressions and architecture review; the adapted engine remains pinned to Bun.

# ADR 0053: 64-Bit NaN-Boxed Internal Value Representation

## Status

Accepted. Amended 2026-10-12 (48-bit pointers; see the end).

## Context

Kiln lowers JavaScript and TypeScript bytecode into C99 translation units (`kiln-backend-c`).
At present, the value representation shared between runtime helpers, generated code, and the public embedding ABI is a 16-byte record (`kiln_value`):

```c
typedef struct kiln_value {
    uint32_t tag;
    uint32_t len;
    union { uint64_t bits; const char *ptr; };
} kiln_value;
```

While clean and portable, a 16-byte boundary value imposes severe penalties on engine execution when used internally:
1. **Cache Traffic**: The operand stack (`stack[max_stack]`), local variables (`locals[local_count]`), and closure environments consume 16 bytes per entry. A 64-byte L1 data cache line can only hold 4 `kiln_value`s instead of 8.
2. **Register Exhaustion**: Passing or returning a `kiln_value` consumes two general-purpose registers (GPRs) under the System V AMD64 and AArch64 calling conventions. This forces parameter spills to memory whenever functions take more than 2 or 3 values.
3. **Double Boxing / Unboxing Overhead**: Storing a 64-bit IEEE-754 double requires writing a 32-bit tag (`KILN_VALUE_NUMBER`), a 32-bit length (`0`), and copying 64 bits into the payload union. Reading a number requires branching on `tag == KILN_VALUE_NUMBER` and dereferencing the bits field.

As established in ADR 0021 ("Value and heap representation is decided before the object model exists"), the internal value representation used inside emitted code and the runtime is a separate concern from the public embedding ABI (`kiln_value` / `kiln_host`), and the internal representation must be one machine word (64 bits).

## Decision

We adopt a 64-bit NaN-boxed representation (`kiln_val` / `uint64_t`) for internal operations, while preserving `kiln_value` as the unchanged public boundary type.

### 1. 64-Bit Quiet-NaN Schema

IEEE-754 double-precision numbers occupy 64 bits:
- 1 sign bit (bit 63)
- 11 exponent bits (bits 62..52)
- 52 fraction bits (bits 51..0)

A quiet NaN (qNaN) is defined by all exponent bits set to `1` (`0x7FF0_0000_0000_0000`) and the highest fraction bit (bit 51) set to `1` (`0x7FF8_0000_0000_0000`). This leaves 51 bits of unused payload.
On modern 64-bit processors (x86_64, AArch64, RISC-V), user-space virtual addresses are constrained to at most 48 bits (addresses `0x0000_0000_0000_0000` through `0x0000_7FFF_FFFF_FFFF`).

We define the upper 16 bits as the tag space:

| Type | Upper 16 Bits | Lower 48 Bits | Bit Pattern |
| :--- | :--- | :--- | :--- |
| **Double (Number)** | Any non-qNaN / exponent != 0x7FF | IEEE-754 bits | `0x0000_....` to `0xFFF7_....` |
| **Undefined** | `0xFFF8` | `0x0000_0000_0001` | `0xFFF8_0000_0000_0001` |
| **Null** | `0xFFF8` | `0x0000_0000_0002` | `0xFFF8_0000_0000_0002` |
| **Boolean False** | `0xFFF8` | `0x0000_0000_0004` | `0xFFF8_0000_0000_0004` |
| **Boolean True** | `0xFFF8` | `0x0000_0000_0005` | `0xFFF8_0000_0000_0005` |
| **Hole / Uninit** | `0xFFF8` | `0x0000_0000_0006` | `0xFFF8_0000_0000_0006` |
| **String Pointer** | `0xFFF9` | 48-bit pointer | `0xFFF9_xxxx_xxxx_xxxx` |
| **Object Pointer** | `0xFFFA` | 48-bit pointer | `0xFFFA_xxxx_xxxx_xxxx` |
| **Closure Pointer**| `0xFFFB` | 48-bit pointer | `0xFFFB_xxxx_xxxx_xxxx` |
| **Array / Buffer** | `0xFFFC` | 48-bit pointer | `0xFFFC_xxxx_xxxx_xxxx` |

### 2. Properties & Fast Paths

1. **Doubles are Unboxed**: Any double is stored directly as its IEEE-754 bit pattern. NaN values generated by arithmetic are canonicalized to `0x7FF8_0000_0000_0000` to prevent collision with tagged pointers.
2. **Double Check is a Single Unsigned Comparison**:
   ```c
   #define KILN_IS_NUMBER(v) ((uint64_t)(v) < UINT64_C(0xFFF8000000000000))
   ```
   Checking if a value is a number is a single instruction: `cmp rax, QWORD PTR .LCPI_QNAN_BASE; jb .is_number`.
3. **Pointer Unboxing**:
   ```c
   #define KILN_PTR(v) ((void *)((uint64_t)(v) & UINT64_C(0x0000FFFFFFFFFFFF)))
   ```
   Extracting the pointer is a single `and` instruction with immediate mask.
4. **Pointer Tagging**:
   ```c
   #define KILN_TAG_PTR(tag, ptr) ((uint64_t)(tag) | ((uint64_t)(uintptr_t)(ptr) & UINT64_C(0x0000FFFFFFFFFFFF)))
   ```

### 3. ABI Boundary Conversion

The public embedding ABI retains `kiln_value`:
- `kiln_val_to_boundary(kiln_val v, kiln_value *out)`
- `kiln_val_from_boundary(const kiln_value *in) -> kiln_val`

These conversions occur only at the external module boundary (`kiln_module_*` entry point) and host call trampolines (`host->call`). Emitted loops, intra-module function calls, and runtime arithmetic operate purely on `kiln_val`.

### 4. Implementation Phasing

1. **Phase 1 (Immediate)**: Float specialization in instruction fusion (`can_fuse_load_const_binary`, `can_fuse_load_const_compare_jump`) emitting unboxed arithmetic and bitwise modulo for power-of-two constants.
2. **Phase 2**: Introduce `kiln_val` definitions and bit masks into `prelude_types.h` and helper conversions in `prelude_core.c`.
3. **Phase 3**: Migrate local registers and stack arrays in `kiln-backend-c` to 64-bit `kiln_val`.

## Amendment (2026-10-12): 48-bit pointers, and one prefix for the rare kinds

The table above gives every pointer kind a 48-bit payload, but the implementation drifted to 47
bits: BigInt (`0xFFFE`), Temporal (`0xFFFE8`), cells (`0xFFFF`) and shared facades (`0xFFFF8`)
were told apart by bit 47. That holds wherever user space sits below 2^47 -- Linux x86_64, macOS
on Apple silicon -- and fails on Linux arm64, which loads programs at `0xaaaa_aaaa_0000` and maps
memory near `0xffff_...`: the first pointer into a program's data lost its top bit when unboxed,
and every native program crashed at startup.

The layout is now what this ADR said. Each pointer kind is a 16-bit prefix over a full 48-bit
address (`KILN_TAG_MASK = 0xFFFF_0000_0000_0000`):

| Kind | Prefix |
|---|---|
| String | `0xFFF9` |
| Object | `0xFFFA` |
| Closure | `0xFFFB` |
| Array / buffer | `0xFFFC` |
| Symbol | `0xFFFD` |
| BigInt / Temporal / shared facade | `0xFFFE`, low bits `0` / `1` / `2` |
| Cell | `0xFFFF` |

The quiet-NaN space has seven 48-bit prefixes above `0xFFF8` (which keeps the immediates, built-in
and method references and the typed-failure value), and kiln has nine pointer kinds. The three
rare ones -- no generated fast path tests for them -- share `0xFFFE` and are told apart by the low
three bits of the payload, which are free because every boxed payload is 8-byte aligned.
`KILN_PAYLOAD_MASK = 0x0000_FFFF_FFFF_FFF8` clears them on every unbox, so a sub-tag never reaches
a dereference; `KILN_VAL_IS_BIGINT`, `KILN_VAL_IS_TEMPORAL` and `KILN_VAL_IS_SHARED` compare with
`KILN_RARE_TAG_MASK`. Every other kind keeps one mask-and-compare.

The alignment premise is checked: builds without `NDEBUG`, or with
`KILN_ASSERT_BOX_ALIGNMENT` explicitly defined, abort at any box whose pointer is unaligned or
wider than 48 bits. Tests exercise high addresses, distinguish every pointer kind, and require
unaligned and out-of-range boxes to fail before dereferencing them.

`kiln-value-abi` owns the layout registry. It generates Rust constants and the C declarations
included in both emitted units and the separately compiled runtime header. A source guard scans
C headers, runtime C and Rust (including emitter strings) for copied tag and pointer-mask literals.
The registry also participates in the emitter fingerprint, so a layout change cannot reuse
modules from the previous representation.

# Dense owner graph for interpreter cycle collection

The cycle collector still discovers owners from the same weak censuses and computes reachability from the same `Rc::strong_count` equation. This candidate changes only the temporary graph representation: a `HashMap<Key, usize>` resolves identities during discovery; owners live in a `Vec<Node>`; adjacency lists store node indices; incoming-edge counts and liveness are dense vectors. `HashMap::entry` makes each discovered identity a single table probe. Physical edges are appended individually, including duplicate edges, because the collector must subtract every real `Rc` edge when deciding whether a strong owner is external.

Weak-map ephemerons store `(map, key, value)` node indices. Their value-owner count is still included before activation, but the value becomes reachable only when both map and key are live. The same fixed-point loop propagates ordinary edges after each activation. Unreachable nodes are cleared only after marking, and weak-map entries are retained using the same key-liveness rule. No collection threshold, census, owner type, or cycle-clearing policy changes here.

The motivation is a diagnostic profile of the interpreter timeout workload, not a claim that this representation improves throughput. Frozen CLI `b0ac1791e1ab0a26e51711dbaa8bd833aabbb8c016d6e7921d6244faa07639fb` (binary SHA identical to its filename) ran the original `ClusterWorkflowEngine` cases with the original five-second per-case deadlines. A `samply` attach to verified PID 1090493 captured target worker TID 1090502; profile SHA-256 is `cae45f2dd0539c62c3fa43ec4a812464b6b2f15cf6df9da77e182cdce17ffc84`. The perturbed run completed 37/47 with 10 timeouts. Among 7,667 worker samples over 126.8 seconds, 1,074 leaf PCs symbolized inside `collect_closure_cycles`; other visible leaves included `run_bounded_inner` (996), `Value::clone` (405), `ObjectData::lookup_key` (197), `SipHasher::write` (229), and `owner_children` (139). About 13.5% of leaf PCs were outside the executable's `.text` and were excluded from function attribution. The profile supports reducing repeated keyed graph operations as a candidate; it does not establish a speedup or prove collection cadence is wrong.

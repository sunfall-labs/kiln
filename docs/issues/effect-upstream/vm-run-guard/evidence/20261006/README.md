# VM run guard validation

The `VM_RUN_ACTIVE` bool replaces a per-invocation TLS nesting counter. Only the outermost `run_bounded` invocation changes the bit on entry/exit; nested synchronous VM drives still observe an active run but no longer update the TLS counter on drop. `run_bounded` is the only production entry to this guard, and its Rust-local guard gives lexical, LIFO destruction. Panics unwind the outer guard and clear the bit.

Candidate source is commit `9dc413e6bb7d935d19e87ccacd68efcef6ca3471`, tree `79fcdf3fad65ecb363e330b23882793062de62a1`. The root integration source comparison against old CLI source commit `80f09d88926675f85f4144e172fe90a51a45e4c5` was checked in that exact repository: the only difference under `crates/interp`, `crates/compile`, `crates/host`, `crates/foundation`, `Cargo.toml`, and `Cargo.lock` is `crates/interp/kiln-interpreter/src/gc_census.rs` (30 changed lines).

# Module instance generations for direct ESM execution

Vitest's `vi.resetModules()` and `vi.importActual()` require fresh module state while retaining ordinary ESM behavior. A reset must create a new module instance graph for the affected loader/session without changing source identity, realm globals, host services, or normal import caching. The instance key is distinct from the canonical source path: resolution, `import.meta.url`, and diagnostics use the latter; module-map identity and export cells use the former.

## Current ownership

The interpreter has one `ModuleMap` per realm keyed by module path. `PlannedModule::key` serves both as source identity and state identity. Closures carry `module_path` for later dynamic imports, but not a module generation. A fresh generation therefore needs unique keys for every module in a plan and a closure-captured instance provenance for later `import()`; a session-wide active generation would make old closures import from the wrong graph.

The native launcher emits reusable functions for each source module. Each `kiln_graph_context` owns its module states and generated linkage fields (exports, imports, cells, namespace values, and CommonJS contexts), and its root visitor registers those values with the realm collector. `kiln_cli_realm_run` now owns the shared CLI/realm services separately and a graph context points to them. Generated native closures now capture graph provenance through an explicit nullable `kiln_host.module_context` capability; calls rebind to that captured host. Ordinary embedding hosts with no module capability continue to use the host passed at call time. The current launcher still owns one graph for the entire run, so this provenance is not yet a generation lifetime mechanism.

Native namespace objects are ordinary GC objects with a module-namespace brand; exported values are traced through their property storage. A live export is a GC cell. Module-generated closures, namespaces, and their owned live-binding cells now carry an edge to a GC-managed module-owner token, and the token traces the graph's external value slots. The current realm root visitor still roots every graph slot directly, and its graph remains allocated through realm teardown. This makes the new edges safe under collection but does not yet reclaim or reset an instance. Owner tokens are currently created once for the realm's sole graph and have no release callback. Generation support must make roots conditional on current/active work, allocate instance storage independently, and release it only when no namespace, cell, closure, or pending evaluation can reach its owner.

The promise queue marks each pending job's handler, argument and derived promise. Promise objects mark their reactions, while active frames mark their function, locals, stack and promise. A popped job remains live through the drain's local copy and the conservative stack walk. These edges retain module closures when the work carries one, but do not by themselves retain external graph tables. Active top-level module evaluation also needs an explicit loader root until it settles. `kiln_c99_gc_enter_job/leave_job` protects collection windows; it is not a graph-lifetime hold.

## Required design

- Keep canonical source paths stable and cache parsed/lowered/emitted module code independently of instance identity.
- Give each requested reset a monotonically unique session generation and derive an instance key per canonical module path in that generation. Dependencies in one generation must resolve to that generation's providers; ordinary imports keep the current cache key.
- Keep realm globals, intrinsics, host adapters, job queue, and shared host services on the realm/session. Keep export/import/cell/namespace/loader status and evaluation promises on each graph instance.
- Capture module-instance provenance in closures created by generated modules. Invocation and dynamic import must use that closure's graph instance, while reading/writing realm-wide state through the shared realm record. An old closure must continue to observe its old imported cells after reset.
- Give closures, namespace objects, exported cells and active/pending module evaluation a GC-reachable owner token for their instance. The token must mark that instance's external value slots once per collection and own/release its external graph storage when unreachable. The current loader pins the active token; settled, replaced instances are then retained only through reachable language objects or work.
- Add per-instance root registration/unregistration or route root visitation through the owner token. Do not leave every old instance permanently registered. The marker must be once per owner per collection, so cycles among namespaces, cells and closures do not recursively revisit the same instance or turn graph marking quadratic.
- Keep module namespaces immutable according to ESM semantics. Test mocking needs a separate Vitest runner/mock policy rather than making namespace objects mutable.

## Implementation sequence

1. Separate shared realm services from module-graph state without changing behavior. This is implemented in `Separate realm services from native module graph state`.
2. Make graph-owned linkage state addressable through an explicit instance pointer and add native tests that keep two instances live in one realm, checking independent cells, import routing, failures, and GC roots.
3. Add closure instance provenance to native calls and interpreter closures/dynamic-import jobs; verify a closure exported by generation A still reads A's dependencies after generation B starts. The native call-host capability and owner edges are implemented for the current single graph; conditional roots, independently allocated generation storage, and owner release remain required before old graphs can be reclaimed.
4. Expose a narrow module-runner capability for `resetModules`/`importActual` that requests a new plan generation. Test same-realm global identity, changed module constructors/state, stable `Symbol.for` identity, and normal import cache behavior.

The first two ownership stages are now represented in the native launcher: realm services and an explicit `kiln_graph_module_instance` have separate records, but each realm run still constructs only one instance. This is groundwork only; it does not yet implement fresh instances. The native work is cross-layer because module-generated code, closure dispatch, host callbacks, and GC roots must all agree on instance ownership.

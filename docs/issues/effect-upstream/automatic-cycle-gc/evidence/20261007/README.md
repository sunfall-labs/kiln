# Cycle collector diagnostic evidence bundle

The bundle contains complete seven-file interpreter cohort reports, per-file envelopes/logs, job/status receipts, frozen CLI metadata (not CLI binaries), and fixed-workload microdiagnostic records. Executables are excluded; their SHA-256 identities and original paths remain in reports/receipts.

Borrowed-visitation cohort: 562 registered/mapped cases, 536 pass, 26 fail, 0 skips, 0 mapping/mode errors; 315 files deferred. Relative to the dense candidate's matched published control, 25 failure IDs were unchanged and one additional failure appeared: `Arbitrary > schema > does not assign recursive depth according to sibling order` (original 5000 ms timeout). The borrowed cohort itself ran 461.405 s. A native-agent offline CPU scan overlapped for about 38 s and consumed about 1.1 GiB during the Arbitrary file, so cohort elapsed-time deltas are not performance attribution.

The fixed-workload diagnostic's 30,000-cycle output checksum matched Node, Bun, and every frozen CLI. Three timed medians (process startup included) were published 400.83 ms, dense 346.85 ms, borrowed 363.34 ms. Peak RSS maxima were 60.70, 59.70, and 60.29 MiB. This narrow shape is evidence against claiming borrowed visitation is faster than dense; it is not a general benchmark. The measurement service requested a 4096 MiB memory cap, CPUWeight 10000, and single-thread Kiln settings; its journal records 304.1 MiB peak for the whole runner. CPUWeight enforcement could not be independently queried after transient-unit teardown.

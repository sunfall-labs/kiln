# Spend bounded generic optimization on retained functions

The generic O1 tier previously selected functions before module liveness and masked dead selections afterward. Unreachable declarations could consume the function and instruction budget while their bodies were never emitted. Selection now repeats after availability is known, excluding unavailable declarations before counting them. All original caps remain: 64 functions, 320 instructions per function, and 4,096 total instructions, with conservative frame-publication checks and deterministic source order. The boxed ABI is unchanged.

The final focused `mbx test -p kiln-backend-c --offline generic_ -- --test-threads=1` completed with exit 0: 12 backend unit tests and one emitted-C integration test passed, zero failed. The new selection fixture exhausts both caps with dead declarations and verifies the cap on retained functions; the emission fixture verifies a call to function 64 receives O1 after the first 64 declarations are pruned. Distinct constant-return bodies avoid unrelated body coalescing. One retained body stays in a single source unit rather than creating a chunk. Earlier fixture-development failures are retained in the owned scratch directory and are not passing evidence.

This is compiler-budget correctness evidence, not a measured upstream deadline win or a final gate.

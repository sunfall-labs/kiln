# Bounded loop-driver and callee optimization profile

This is an isolated compiler-tier experiment on source `f3b7605709d31feec6bc1396a91c6bd3c2ad6cdd` plus the uncommitted changes identified by the source diff. It changes only which existing boxed function bodies receive native O1 compilation; call resolution, generic ABI, frame publication, and runtime semantics are unchanged. No library or function names are used in production selection.

The supplemental profile is bounded by the existing module analysis envelope: at most 512 profile functions and 32,768 instructions. It permits at most 256 loop groups / 512 selected bodies and 32,768 aggregate instructions, with each group limited to four bodies and each body to 1,536 instructions. Each loop group's score is deterministic. A first pass considers the best group for each distinct caller before additional edges from already represented callers. The caller itself may be included with its known-callee closure when it is available and fits the same limits. Availability is checked per compilation phase; this profile only affects O1 selection, while direct-call guards remain phase-derived.

The pinned `SchemaBinary.ts` diagnostic selected 140 functions / 18,116 instructions under the limits. Its actual decode group was `[193, 199, 200, 45]`; functions 193 (`decodeArray`), 199, and 200 were verified selected in emitted output. The source graph had 25,550 body instructions and 1,719 evaluation-entry instructions. The diagnostic emitter reported 14,422,064 evaluation bytes and 14,261,261 instantiation bytes in 1,625 ms, but those byte counts include the full inline `HEADER` runtime/prelude template: the test uses default `decoupled_prelude=false`. Native AOT sets `decoupled_prelude=true`, so these are not application-unit size estimates. The retained AOT record for the same SchemaBinary instantiation reports 8,653,457 source bytes (SHA-256 `0088fb6b3828648a3ccc01f1d93363141447c8ffe9a175e83c8904877b7e6400`) with a separate runtime prelude include. No native AOT compile-cost or runtime improvement is claimed by this receipt.

Validation used pinned Rust 1.97.1 via `mbx`, one Cargo/Kiln/Rayon worker, shared MBX cache, and serial test threads. The planner tests passed 3/3. The pinned Schema emitter diagnostic passed 1/1. The full `kiln-backend-c` suite passed 352 tests, with 0 failures and 4 ignored; emitted-C integration tests passed 37/37 and doc tests had no cases. Full raw logs are retained beside this report. A separate quiet Hash replay completed 25/25 on the root's frozen CLI; that verifies the unrelated Hash control only, not this selector's runtime impact.

The candidate still needs a fresh combined native AOT and unchanged-deadline SchemaBinary replay before acceptance. Generated-C volume is substantial, so resulting Clang compile time and native case outcome remain open questions.

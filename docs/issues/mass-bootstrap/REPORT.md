# Native bootstrap and digest measurements

This change is `f9f0ce84` on baseline `e7591c17`. It keeps one immutable compiled bootstrap program, source/IR digests, and provider-capability result for each of three fixed surfaces. It replaces the handwritten production SHA-256 with workspace-pinned `sha2`; output bytes, protocol spellings, and artifact identity remain unchanged. ADR 0010 records the measured reason for accepting the dependency rebuild cost.

Warm daemon builds used the same single-file input and native-release profile, with separate baseline/candidate daemons sharing one artifact cache. After each first request and warm-up, four steady requests per binary gave baseline summaries of 189, 177, 172, and 164 ms (median 174.5 ms) and candidate summaries of 61, 60, 61, and 59 ms (median 60.5 ms), a 65.3% reduction. Emission medians fell from 22 ms to 14 ms. The first candidate request took 41.8 s: adding `sha2` changed the provider source identity and triggered a one-time provider archive rebuild; it is setup cost, not a steady build sample.

The release-mode SHA comparison hashed deterministic `0x5a` buffers 100 times each. At 4 KiB, 64 KiB, 1 MiB, and 16 MiB, scalar/`sha2` totals were 1.095/0.179 ms, 17.390/2.763 ms, 283.123/44.841 ms, and 4.688/0.740 s. A separate three-hash check at 64 MiB took 552/84 ms. The speedup ranged from 6.1× to 6.6×.

The benchmark input was `export function main() { console.log("bootstrap measure"); }\nmain();` (SHA-256 `5de6b22c012280bfcfd067af9437aae197000cd13bb22297a81df8cc1dc55ece`). Both daemons used Clang 18.1.3 on x86_64 Linux, `KILN_JOBS=4`, and `--profile native-release`. Exact binary hashes, sample timings, and the reproduction command sequence are in `measurements.json` and `reproduce.sh`. The binary copies and full logs used for this run remain in the worktree's ignored `target/bootstrap-bench/` directory and are not part of this report commit.

Validation: `mbx test -p kiln-digest` passed (7 tests); the focused native bootstrap cache test passed; `mbx clippy -p kiln-native -p kiln-digest` completed with existing warnings; and the release CLI build succeeded.

The follow-up emitter identity change addresses persistent C-cache misses after native orchestration edits. Source/CommonJS cache entries now fingerprint a small dedicated module containing the effective profile-policy mapping and the exact backend wrapper called on a miss. Their input identity still includes complete compiled IR and source, logical path, source kind, profile, and effective policy; the backend emitter and prelude fingerprints remain in the key. Bootstrap emission has its own exact wrapper fingerprint. Thus edits to `lib.rs`, graph construction, or shared-graph orchestration no longer invalidate every Source/CommonJS C artifact, while edits to the actual emitter still do. Behavioral regression coverage checks profile/policy/target identity separation, input invalidation and reopening persisted entries. Dedicated wrappers bind directly to backend entry points; the parent review removed source-text assertions that merely mirrored the fingerprint implementation. The input namespace advances from v4 to v5, so existing generated-C entries incur one intentional cold miss after rollout.

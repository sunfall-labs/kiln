kiln vs Porffor: Native TypeScript and npm Compared

Compare kiln and Porffor for native TypeScript compilation, npm package workflows, HTTP servers and compatibility evidence, with current upstream documentation.

kiln v0.1.0 · upstream documentation reviewed October 12, 2026

Both compile ahead of time. Compare the application boundary.

Porffor compiles JavaScript and TypeScript to native executables with the needed language runtime built into the artifact. Its docs position compatibility as something to test while the project is pre-alpha. Porffor’s native compilation workflow.

kiln combines an interpreter for immediate runs with native builds, TypeScript source diagnostics and a Node-oriented application host. The decision depends on how your code uses modules, dependencies, I/O and concurrency, as well as the language features it exercises.

Existing npm projects need more than syntax support.

Porffor’s plain builds accept a single source file; its adaptation guide recommends bundling and auditing Node-specific assumptions. Server builds perform bundling automatically. Porffor’s module and runtime boundary.

kiln resolves ESM and CommonJS packages through its Node layer. Its committed 2026-10-11 record contains 361/361 passing pinned package smoke tests in native-dev mode, with native stdout compared byte for byte against Node. That is inspectable evidence for the exercised APIs, not blanket npm compatibility. Runtime-selected module paths still need explicit native inclusion. All package results and native inclusion rules.

Both have a native HTTP path.

Porffor now documents fetch-style servers using uWebSockets. Its contract lists limits including loopback binding, one-piece text responses and absent outbound fetch. Porffor’s current HTTP surface.

kiln offers core Node HTTP APIs and a Request/Response interface through Kiln.serve. Its website publishes workload-specific HTTP measurements against Node, Bun and Deno; these do not measure Porffor. Choose representative routing, request-body and asynchronous workloads rather than extrapolating from hello world. Measured workloads and conditions · Server example.

Which should you evaluate first?

Evaluate Porffor for a bounded compiled core or a service that fits its documented server contract. Evaluate kiln when source TypeScript checking, Node-oriented dependencies, typed actors or shared immutable data are central to the application. Both benefit from testing the actual program’s output and lifecycle before measuring speed.
